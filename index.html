Column mapping

Map a Dry/Processed Yield column if your monitor already outputs a per-area yield rate (e.g. bu/ac, kg/ha) — this is what most yield maps use. Map a Wet/Unprocessed Yield column if it also (or instead) logs the raw as-harvested signal, which on some platforms is a flow rate (lbs/sec, tons/sec) rather than a per-area rate. Either or both may be left unmapped, but at least one is required. Threshold-style filters (Max/Min/Std.-dev Yield) and Post-Cal's per-acre targets are judged against whichever one is selected above as primary — the other mapped column still passes through every row-removal filter and the grain-flow-delay shift, so a cleaned version of it is produced either way. Total Wet / Wet Yield Avg/ac under Post-Cal are only enabled once a Wet/Unprocessed Yield column is mapped.

Detect grain-flow delay

Finds the time lag between the header cutting the crop and the flow sensor measuring it, using phase correlation (Lee et al. 2012, Trans. ASABE 55(3)). The analysis runs on the file exactly as imported — before balancing, filters or any other cleaning — so nothing done on the other tabs can bias the answer. An incorrect delay shows up as the “sawtooth” pattern between alternate passes; the correct delay is the one that makes neighbouring passes agree best.

    Balancing

    Machine and date differences are usually a calibration issue, not real yield variation — balance them out here, before the Filters tab, so filters like Std. Deviation of Yield judge the corrected values rather than the raw ones.

    Date balancing

    Scales each harvest date's mean yield to match the base date (mean-ratio scaling).

    Machine balancing

    Scales each machine's mean yield to match the base machine. Applied after date balancing if both are enabled.

    Moisture balancing

    For when two machines' moisture meters — not their yield sensors — disagree. Computes the scaling factor from the ratio of each machine's average moisture reading to the base machine's, then applies that factor to yield. Requires a mapped Machine ID and Moisture column. Applied after date and machine balancing if more than one is enabled.

    About this tool

    Yield Editor Pro Web is a single, self-contained HTML file for cleaning up combine yield-monitor data: import a raw yield file, correct machine/date/moisture calibration drift, run it through a configurable filter set to drop bad points, true it up to a known scale-ticket total, and export the cleaned result as CSV, GeoJSON, Shapefile, AgLeader Text, or an interpolated GeoTIFF raster — all in the browser, with nothing uploaded anywhere. It's aimed at the same job the original desktop Yield Editor does, with a filter/balance/calibrate pipeline, a web map for drawing selections, and session save/load, in a form that needs no installer and runs on anything with a modern browser.

    Workflow

    The tabs run roughly in the order you'd use them: Import your data and map its columns, then Balance out machine/date/moisture calibration differences, then run Filters to drop bad points, then Post-Cal to true the result up to a known scale total, then optionally load a Boundary, then Export and review the Summary. Re-running any tab's Apply button always recomputes the whole pipeline in that order — you don't need to reapply earlier tabs after changing a later one.

    Import & column mapping

    Accepts AgLeader Advanced Text, any delimited CSV/TXT/DAT with a header row, GeoJSON, and Shapefiles (zipped or as loose .shp/.dbf/.shx/.prj). Column roles are auto-detected from common monitor naming and can be corrected under Column mapping. Timestamp and Machine ID drive most of the rest of the tool — Timestamp is required for date balancing, pass detection, and the seconds-based start/end delay filters; Machine ID is required for machine and moisture balancing.

    Dry/Processed Yield and Wet/Unprocessed Yield are separate, both-optional mappings (at least one is required). Map Dry/Processed if your monitor outputs a per-area yield rate (bu/ac, kg/ha, etc.) — most yield maps use this. Map Wet/Unprocessed if it also (or instead) logs the raw as-harvested signal — on some platforms that's a per-area rate too, but on others it's a flow rate (lbs/sec, tons/sec) that the monitor itself converts into the per-area Dry figure. Whichever one you mark as primary (a choice that appears once at least one is mapped) is what threshold filters (Max/Min/Std.-dev Yield) and pass/outlier detection are judged against; the other still rides along through every row-removal filter and the grain-flow-delay shift, producing its own cleaned attribute (see Filters, below).

    Polygon inputs (as-harvested yield-cell files, management-zone files) import one row per polygon. The real footprint is kept for the map and for GeoJSON/Shapefile export; filtering, balancing, and GeoTIFF interpolation use each polygon's centroid.

    Passes

    Before anything else runs, points are grouped into combine passes automatically — by a gap in time, or a jump in position too large for the reported ground speed to explain. If a Machine ID column is mapped, grouping is done separately per machine first, so a file that interleaves multiple machines' records by timestamp doesn't read as one machine teleporting to another's position. Pass grouping is what the Start/End Pass Delay filters (both the observation-count and the seconds versions) and the Smooth Velocity filter key off of.

    Flow Delay (automatic detection)

    Grain takes several seconds to travel from the header to the flow sensor, so each logged yield actually belongs to a spot the combine passed a few seconds earlier. Left uncorrected, alternate passes are displaced in opposite directions and the map shows a “sawtooth” stripe pattern. The Flow Delay tab finds the correcting delay automatically using phase correlation delay identification (PCDI).

    How it works. For every trial delay (default −10 to +25 s) the yield of each point is re-read from that many seconds later along its own pass, and the points are drawn onto a square raster. The raster is compared with a copy of itself shifted one pixel diagonally, which pairs each pass with its neighbour. Empty pixels are filled with identical Gaussian white noise in both images so they cannot create fake similarity. The phase-correlation value at zero offset is the relative spatial consistency (RSC): the delay with the highest RSC is the one that makes neighbouring passes agree best. The whole test is repeated with several independent noise fields (default 10); the average curve picks the answer and the spread of the individual answers measures its reliability.

    Sign. A positive delay means the yield recorded at a position was really measured that many seconds later — the same direction as the Grain flow delay filter. The result is relative to the file as imported, so if the monitor export already applied a delay (AgLeader exports commonly apply 12 s) it is the additional correction, usually near zero.

    Pixel size. If a Swath width column is mapped the pixel size is 0.7 × the median swath, so that adjacent passes fall in adjacent pixels. Otherwise it is taken from the point where the ratio of valid pixels and the ratio of coupled pixels cross, as described in the paper. The image side is rounded up to a power of 2 for the FFT; pixels beyond the field are treated as empty. You can type a pixel size to override either.

    Reading the result. Confidence is Low when the individual noise-field answers disagree by more than 3 s (the paper's criterion for a questionable estimate), when the peak sits on the edge of the search range, or when the curve is nearly flat; Medium for moderate spread or fewer than 5,000 points. In the paper's 50-field test about 90% of estimates were accurate; the failures were nearly all small fields with few points or very little yield variation. If confidence is Low, widen the range, compare the Raw | Clean view by eye, or enter a delay you trust.

    Applying it. Use recommended (or typing a value and pressing Apply settings) makes the correction the very first pipeline step — before balancing and every filter — re-reading yield (and the other yield column and, optionally, Moisture) at the shifted time within each pass. Readings that would fall beyond the start or end of a pass are dropped. One delay is applied to the whole file; if a file mixes combines with different delays, analyse and correct them separately.

    Reference: Lee, D. H., K. A. Sudduth, S. T. Drummond, S. O. Chung and D. B. Myers. 2012. Automated yield map delay identification using phase correlation methodology. Trans. ASABE 55(3): 743-752. This is an independent implementation, not the authors' software.

    Raw | Clean side-by-side view

    The ⇆ Raw | Clean button in the top bar splits the map. The left side always shows the data exactly as imported; the right side shows the result of your processing and redraws every time you press an Apply button (flow-delay correction, balancing, filters, Post-Cal). Both sides use the same colour scale — taken from the raw data's 2nd–98th percentile — so a change in colour is a real change in value, and the two maps pan and zoom together. The header over each side shows record count, mean and standard deviation.

    The drop-down in the right-hand header lets you step back through the pipeline: pick any earlier stage (imported, after flow-delay correction, after each balance or filter that is enabled) to see the map as it was at that point. Final result always follows the latest run. While this view is open the map is coloured by yield only; close it to get the “Colour map by” attribute picker back. Box and polygon drawing still work on the right-hand map.

    Balance

    Date balancing and machine balancing each scale a group's mean yield to match a base group you pick (mean-ratio scaling) — useful when harvest conditions or a monitor's calibration drifted across days, or when one combine in a fleet reads consistently high or low. Both operate on the primary yield column only.

    Moisture balancing is different: it computes its scaling factor from the ratio of average moisture readings between machines, not average yield, then applies that factor to yield. Use it when you believe two machines' yield means genuinely differ for real agronomic reasons, but one machine's moisture meter is separately out of calibration — scaling by the yield ratio directly would erase real field variation along with the sensor error, while scaling by the moisture ratio targets the sensor issue specifically. Requires Machine ID and Moisture mapped.

    All three balancing options write to a shared yield_balanced column and can be chained — date, then machine, then moisture, in that order, whichever are enabled. Filters and Post-Cal that follow use this balanced column automatically once it exists.

    Filters

    The USDA Yield Editor's standard filter set, each optional and independently configurable. By default all enabled filters are applied in the traditional fixed order the USDA Yield Editor uses them in, regardless of how the list below is arranged — this is the "bulk" method. Check "Apply filters in the order listed below" to instead run them in whatever order you drag the rows into (grab the ⋮⋮ handle on the left of each row) — useful when the order genuinely changes the result, e.g. running Position/Manual-selection before a Std.-deviation-of-yield filter so outliers inside a hand-drawn zone don't skew the mean used to judge the rest of the field. Every row-removal filter (everything except Grain flow delay) drops the same rows regardless of which yield column is primary — the non-primary yield column and Moisture simply lose those rows too, since a whole record is removed at once, not one column at a time.

    Grain flow delay shifts yield readings by N observations to correct for the lag between grain entering the header and reaching the flow sensor. Since this is a re-index rather than a value threshold, it's applied to the primary yield column, the non-primary yield column (if mapped), and Moisture together, using the same N-observation shift for all three — they share one auger, so one sensor-lag correction is physically valid for all of them. Start/End Pass Delay drop the first/last N observations of every pass, to cut out header-raising/lowering transients — measured in observation count. Start/End Pass Delay (sec) do the same thing but measured in seconds elapsed from the true start or end of the pass (using the full pass, unaffected by whatever earlier filters have already removed), for monitors that don't log at a steady rate. You can enable either version, both, or neither for start and end independently.

    Maximum/Minimum velocity drop points outside a ground-speed range. Smooth velocity drops a point if its speed changed by more than the given fraction from the previous point in the same pass — catches jerky GPS/speed readings. Minimum swath drops points where active header width fell below a threshold (partial-width passes). Maximum/Minimum yield and Std. deviation of yield are judged against the primary yield column only — a threshold entered for one unit system (e.g. bu/ac) wouldn't mean anything applied to a flow rate in the other. Position (bounding box) and Manual selection use shapes you draw on the map — Position keeps only points inside a box, Manual selection excludes points inside one or more drawn polygons.

    Once filtering finishes, whichever of Dry/Processed and Wet/Unprocessed yield are mapped are copied out as yield_dry_clean / yield_wet_clean, alongside moisture_clean if Moisture is mapped — three explicitly-named, filtered (and delay-corrected) attributes for platforms that want the wet + dry + moisture trio to build their own yield maps. The hint line below "Apply All Filters" shows the running record count after each enabled stage, in order, so you can see which filter is removing how much data.

    Post-Cal (post-harvest calibration)

    A final, single-factor scale applied to the whole dataset after everything else, to true it up to a real-world total — a scale ticket, elevator receipt, or weigh-wagon reading. Enter any one of four target values (or several, in which case the resulting factors are averaged):

    Wet Yield Avg/ac and Total Wet require a mapped Wet/Unprocessed Yield column — the two fields are disabled otherwise. Wet Yield Avg/ac is compared directly to its (filtered) mean; Total Wet additionally needs acres, taken from an imported boundary if you have one, or estimated from Swath width × Velocity assuming roughly one reading per second. Dry Yield Avg/ac and Total Dry compare directly against a mapped Dry/Processed Yield column when one exists — otherwise they're derived from Wet Yield × (100 − average Moisture%) / 100, which needs both Wet/Unprocessed Yield and Moisture mapped. Total Dry, either way, additionally needs acres the same way Total Wet does.

    The resulting factor is applied to the primary yield column (into yield_balanced) and, to keep the trio consistent, to whichever of yield_dry_clean/yield_wet_clean isn't already the primary — Moisture itself is never rescaled.

    Boundary & GeoTIFF export

    Import a field boundary (GeoJSON or Shapefile) to draw it on the map, clip the GeoTIFF raster export to it, and — once Post-Cal is looking for acres — supply the field area. GeoTIFF export interpolates your chosen attribute(s) onto a grid using either Inverse Distance Weighting (IDW) or Ordinary Kriging, selectable per export; cells outside the boundary are masked as nodata (-9999). IDW weights nearby points purely by distance (tune with the power slider — higher power favours the closest points more strongly). Ordinary Kriging instead weights points by a fitted spatial-covariance model (a spherical semivariogram whose sill/nugget are estimated from the data's variance and whose range defaults to 30% of the point cloud's extent, or a distance you enter yourself) — it tends to produce a smoother, statistically-weighted surface but costs more to compute. Smaller cell sizes, higher IDW power, and Kriging in general all increase processing time.

    Export & Summary

    CSV, GeoJSON, and Shapefile exports respect the Column set choice at the top of the Export tab. Full (the previous default behaviour) includes every original column plus whichever cleaned columns exist — wherever balancing or Post-Cal produced a yield_balanced column, and wherever yield_dry_clean/yield_wet_clean/moisture_clean exist, they're included alongside the original columns. Streamlined exports the source file's own columns — same names, same order — with the cleaned wet/dry/moisture values written in place of the raw ones, and adds no _clean-suffixed or yield_balanced columns. Use it when another FMIS platform needs to recognise the file as a normal yield export. Simplified exports only the cleaned wet/dry/moisture values under their original column names (plus position in GeoJSON/Shapefile geometry) and drops every other source column, giving the smallest file; it will not be recognised by platforms that require the full original column set. AgLeader Text export always uses its own fixed field schema regardless of this setting, and prefers an actual mapped Wet/Unprocessed Yield value for its Grain_Flow_lbs_sec field over back-calculating one from the per-acre Dry figure, when one is available. The Summary tab captures the source file, column mapping (including which yield column is primary), every pipeline stage's record count, all balancing and calibration factors, boundary status, and any GeoTIFF exports made in the session (including which interpolation method each used) — downloadable as Markdown or a standalone HTML file.

    Sessions

    Save Session (top bar) downloads your current column mapping, filters, balancing, and Post-Cal settings as a small JSON file — not the source data itself. Load Session restores those settings; re-import the original source file afterward (or first) to see results.
